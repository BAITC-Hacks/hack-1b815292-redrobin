# RedRobin

RedRobin — сервис для автоматического анализа изменений между двумя редакциями организационных документов в формате DOCX.

Система сравнивает версии документов, определяет изменения в организационной структуре и функционале, а также формирует структурированный результат с подтверждением найденных изменений исходным текстом.

## Возможности

* загрузка двух версий документа в формате DOCX;
* автоматический разбор текста и таблиц;
* сегментация документа по пунктам;
* сопоставление содержимого двух редакций;
* AI-анализ смысловых изменений;
* определение добавленных, удалённых и изменённых положений;
* проверка найденных изменений по исходным документам;
* формирование структурированного отчёта;
* просмотр результата через пользовательский интерфейс;
* JSON API для интеграции с другими системами.

## Как это работает

1. Пользователь загружает две версии документа:

   * `before` — предыдущая редакция;
   * `after` — новая редакция.

2. RedRobin извлекает содержимое DOCX, включая абзацы и таблицы.

3. Документы разбиваются на структурированные сегменты.

4. Система сопоставляет две версии и определяет потенциальные изменения.

5. AI анализирует смысловые различия между редакциями.

6. Найденные изменения проходят проверку по исходному содержимому документов.

7. Пользователь получает итоговый структурированный отчёт.

## Локальный запуск

### 1. Клонирование репозитория

```bash
git clone <repository-url>
cd RedRobin
```

### 2. Создание виртуального окружения

```bash
python3.12 -m venv .venv
```

Linux / macOS:

```bash
source .venv/bin/activate
```

Windows:

```bash
.venv\Scripts\activate
```

### 3. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 4. Настройка окружения

Создайте `.env` на основе примера:

```bash
cp .env.example .env
```

Добавьте необходимые переменные окружения, включая OpenAI API key.

> Никогда не добавляйте `.env` и API-ключи в Git.

### 5. Запуск

```bash
uvicorn app.main:app --reload
```

После запуска приложение доступно по адресу:

`http://localhost:8000`

Проверка состояния:

`http://localhost:8000/health`

Swagger / OpenAPI:

`http://localhost:8000/docs`

## API

### Проверка приложения

```text
GET /health
```

Проверяет состояние приложения без обращения к AI.

### Проверка готовности

```text
GET /ready
```

Проверяет состояние временного хранилища и AI-конфигурации.

### Создание задания

```text
POST /api/jobs
```

Принимает два DOCX-файла:

* `before_file`
* `after_file`

### Запуск анализа

```text
POST /api/jobs/{job_id}/analyze
```

Запускает обработку и анализ загруженных документов.

### Статус задания

```text
GET /api/jobs/{job_id}
```

Возвращает текущий статус и прогресс обработки.

### Получение результата

```text
GET /api/jobs/{job_id}/result
```

Возвращает итоговый результат анализа.

## Обработка документов

RedRobin извлекает из DOCX:

* абзацы;
* таблицы;
* структурированные пункты;
* текстовые фрагменты, необходимые для сравнения.

Разобранные документы сохраняются как JSON-артефакты задания, поэтому их можно повторно анализировать без новой загрузки DOCX.

Если две версии документа идентичны, система формирует пустой отчёт без лишнего обращения к AI.

## Docker

Сборка образа:

```bash
docker build -t redrobin .
```

Запуск:

```bash
docker run --rm -p 8000:8000 --env-file .env redrobin
```

## Безопасность

Секретные данные, включая OpenAI API key, хранятся только в локальном `.env`.

`.env` исключён из Git и Docker-контекста и не должен публиковаться в репозитории.

## Результат

RedRobin сокращает ручную работу при сравнении больших организационных документов и помогает быстро увидеть, какие положения были добавлены, удалены или изменены между двумя редакциями.
